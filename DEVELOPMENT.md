# Правила розробки (Development Guide)

Цей проект дотримується суворих правил розробки для забезпечення чистоти коду та зручності підтримки.

## 🎨 Стилізація

1.  **Лише Tailwind CSS**: Використовуйте тільки класи Tailwind для стилізації компонентів та сторінок.
2.  **Жодних інлайн-стилів**: Заборонено використовувати атрибут `style` (крім випадків з динамічними обчисленнями, які неможливо реалізувати через класи).
3.  **Змінні та кольори**:
    *   Використовуйте CSS-змінні для кольорів та констант.
    *   **Важливо**: Якщо потрібного кольору або змінної не існує, додайте її в `assets/style/globals.css` у блок `:root` або `@theme`, і лише потім використовуйте.

## 🏗️ Архітектура компонентів

1.  **Логічні компоненти**: Створюйте змістовні, перевикористовувані компоненти з чіткими пропсами (Props).
2.  **Структура файлів**: Компоненти записуються у форматі `ComponentName.tsx` без створення окремих папок.
3.  **Експорт**: Всі компоненти з папки повинні бути експортовані через загальний файл `index.ts`.
    *   Приклад імпорту: `import { Button } from '@/components/Button'`.

## 📁 Організація файлів

*   `app/` — сторінки та роутінг.
*   `components/` — спільні UI-компоненти.
*   `assets/icons/` — компоненти іконок.
*   `assets/style/` — стилі.
*   `content/` — контент сайту (JSON).
